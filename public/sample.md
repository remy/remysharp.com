# Rem Sharp — A Specimen

## Brighton, 50°50′N 0°08′W

Rem Sharp has been writing for the web since before the phrase “front-end
engineer” meant anything to anyone outside a handful of mailing lists. He builds
in the open, publishes at *remysharp.com*, and has an unfashionable affection for
vanilla JavaScript — no frameworks, no build step, no ceremony.

His office in Brighton faces the difficult, flickering light off the Channel. It
suffices. The waffle-iron of a schedule that runs beneath it — conference
programming, client work, the odd Game Boy cartridge — is stuffed full enough
that the affable exterior occasionally flags.

### ffconf, 2008–

Since 2008 he has run **ffconf**, a single-track conference for web developers
held each autumn in Brighton. Roughly 350 people, one room, no sponsor
lanyards. The finances are difficult; the affection is not.

> “Make the thing you wish existed, then find out whether anyone else wanted it
> too.” — an approach he’d likely disown if you quoted it back at him.

### JS Bin & other artefacts

He wrote **JS Bin** in 2008 as a way to paste code at somebody over IRC. It grew
into something with 1,024,000 users, a Redis cluster, and a bill he paid himself
for the better part of a decade. Other work — the Oak National Academy Open
Curriculum API, *Marbles²* for the original DMG — occupies the same territory:
small, specific, unlikely to be built by a committee.

#### A closing paragraph, set plainly

The through-line is not JavaScript. It is a preference for legible things: code
you can read at 2am, conferences you can attend without a map, APIs that explain
themselves. Everything else — the frameworks, the tooling, the discourse — comes
and goes on a fifteen-year cycle, and he has watched it come and go twice.[^1]

[^1]: Three times, if you count XHTML.
